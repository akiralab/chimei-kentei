# 地名読み検定「この地名、読めますか」

難読地名を**ひらがなで書いて答える、答案用紙風の10問テスト**。都道府県を選んで始め、同じ問題セット（セットID）で他の人と点を競う。

- 公開先: https://akiralab.github.io/chimei-kentei/
- 科目（出題する地名の種類。難易度ではないので画面では easy / difficult と呼ばない）: **市区町村名**（内部 ID `e`。「匝瑳市」は幹の「匝瑳」だけを読む）／ **市区町村名＋町名**（内部 ID `d`。大字・町名も含む。丁目は出さない）
- 問題数: 10 問（既定）か、**全部**（セット ID の末尾に `-all`。得点は正答率を 100 点満点に丸めた値で、順位表は 10 問とは別区分「全問」）。**単位は科目で違う**:
  - **全市区町村名** … 市区町村名 × 都道府県／地域。その範囲の市区町村名を全部（9〜179 問）。母集団は `easy.json` にあるものだけで、**問題バンクが除いた市区町村（ひらがなの さいたま・ニセコ・むかわ など）は出さない**
  - **全町名** … 市区町村名＋町名 × **市区町村**。その市区町村の町名を全部で、**市区町村名そのものは含めない**（中央値 30 問）。**町名が 10〜500 件の 1,403 市区町村だけ**が選べる（下の表）
- 難易度: **両科目**とも ★1〜3 で絞れる（セット ID の末尾に `-s1` / `-s2` / `-s3`）
- **正解できない問題は出題しない**: 読みにひらがなと「ー」以外（全角数字）が混ざる町名 **345 件**は出題から外す（例 西十一条北 ＝ にし１１じょうきた。解答欄がその文字を受け付けないため）。問題バンクの JSON には `skip` を付けて**残し**、抽出が飛ばす（母集団の並びを変えないので、既存の共有リンクは同じ 10 問を再現できる。Issue #50）。画面に出る問題数（`meta.json` の件数）は skip を除いた「出題できる件数」
- **今日の10問**: 表紙から 1 タップで入る日替わりの共通セット。**全国 × 市区町村名 × ★★★ × 日付シード（JST の `YYYYMMDD`）**＝ `{データ版}-e-00-{YYYYMMDD}-s3` で、誰がどの端末で押しても同じ 10 問になる。結果画面の順位表は見出しに日付を出す（`src/screens/Cover.tsx` の `TODAY_STARS` が難易度の唯一の指定）
- 1セット10問固定・100点満点。セットID ＝ `{データ版}-{モード}-{範囲}-{シード}[-all][-s{1,2,3}]` から決定論的に同じ問題が再現される（例 `abr20260925r2-e-12-1234-all` ＝ 千葉県の全市区町村名、`abr20260925r2-d-122351-1234-all` ＝ 匝瑳市の全町名、`abr20260925r2-d-12-1234-s3` ＝ 千葉県の町名も含む ★★★ の 10 問）

### 全町名を選べる市区町村（10〜500 件）

1 回の答案として成立しない市区町村は選択肢から外す。下限・上限は `src/engine/types.ts` の `ALL_TOWNS_MIN` / `ALL_TOWNS_MAX`。

| 町名の件数 | 市区町村 | 扱い |
|---|---:|---|
| 0 件 | 33 | 選べない（「町名なし」） |
| 1〜9 件 | 288 | 選べない（「7問・少なすぎるため対象外」） |
| 10〜500 件 | **1,403** | 選べる |
| 501 件以上 | 17 | 選べない（「3,741問・多すぎるため対象外」。京都市 3,741・名古屋市 1,480 ほか） |

件数は **出題できる町名**（`skip` を除く）で数える。そのため 宇多津町（11 → 2 件）と 室戸市（11 → 8 件）は
下限を割って選べなくなった（2026-10-05・Issue #50）。

- **下限 10（＝ `QUESTIONS_PER_SET`）の理由**: 全問のセットの得点は正答率なので、町名が 1〜9 件の市区町村を全問正解すると**短時間で 100 点**になり、同じ「全問」の一覧で 179 問を解いた人より上に来てしまう。10 問が最小の答案という既存の決まりに揃えた。
- **上限 500** は API の `ANSWERS_MAX` と同じ値（上げるならどちらも上げて Lambda を再デプロイする）。
- 下限・上限はエンジン（`src/engine/bank.ts`）で判定するので、**サーバー（Lambda）も同じ条件で弾く**。★ で絞った結果が 10 問に満たない組み合わせ（室蘭市 49 件の ★★★ は 8 件。選べる 1,403 市区町村のうち 811 件にこういう ★ がある）も同じく選べない。
- **全市区町村名（`e`）に下限は無い**（島しょ 9 問のように既に登録された行があるため）。範囲が狭いときに都道府県へ広げる仕組み（`MIN_POOL_FOR_SCOPE`）は 10 問のセットの話で、全町名には効かない。

## 範囲（セットIDの `{範囲}`）

| 形式 | 意味 | 例 |
|---|---|---|
| `00` | 全国（市区町村名のみ。町名は都道府県ごとのファイルなので全国では組めない） | `00` |
| 2 桁 | 都道府県 | `12` = 千葉県 |
| 3 文字 `\d{2}[a-z]` | 都道府県の中の**地域** | `01c` = 北海道・道央 |
| 6 桁 | 市区町村。**全町名のときだけ使う**（10 問 × 市区町村の UI は置かない。共有リンクで来たときは母集団が 20 件未満なら都道府県へ広げる） | `122351` = 匝瑳市 |

地名が多い北海道（179 市町村）と東京都（62 市区町村）だけ地域に分けられる。定義の正本は [`src/geo/subregions.ts`](src/geo/subregions.ts)（判定は団体コードのみ。市区町村名には頼らない）。

## 難易度（セットIDの `-s{1,2,3}`）

**市区町村名も町名も** 1 問ごとに ★1〜3 が付いている（`easy.json` / `difficult/{都道府県コード}.json` の `stars`）。範囲・科目の画面で「全部｜★｜★★｜★★★」を選ぶと、その ★ だけから出題する。

| ★ | 市区町村名（全 1,700 件） | 町名（出題できる 107,336 件） | だいたいの中身 |
|---|---|---|---|
| ★ | 566 件（33%） | 38,863 件（36%） | 読みが素直（横浜・新宿・名古屋／中央・十三） |
| ★★ | 601 件（35%） | 46,754 件（44%） | 読みにゆれがあるか、字が少し難しい（札幌・我孫子・渋谷／中島・新橋・本町・伏見・常盤町） |
| ★★★ | 533 件（31%） | 21,719 件（20%） | 読めない字・当て字（匝瑳・特牛・馬主来／放出東・舎人・御器所） |

町名は JSON の配列が 107,681 件で、うち **345 件は出題しない**（読みに全角数字が混ざる。上の概要の最後の項目）。
345 件はすべて ★★★ なので、除いたぶんは ★★★ だけから減っている。

表紙の「今日の10問」は全国 × 市区町村名 × ★★★ に固定する（533 件あるので日替わりの 10 問は毎日組める）。

- **付け方の正本は [`data/build_stars.py`](data/build_stars.py)**（Issue #33・#46・#54）。`build_questions.py` はこれを呼ぶだけで、軸も閾値も持たない。**軸は科目で違う**:
  - 市区町村名（`judge_all`）… A1 人口（国勢調査 2020 の全国分位）× B2 公式の読みを漢字の音訓で分解できるか（KANJIDIC2）× B4 幹の中で最も難しい漢字（KANJIDIC2 の配当学年）の 3 軸。B2×A1 の素点に B4 を足す
  - 町名（`judge_towns`）… **A1 は使わない**（町名に人口は無く、所属市区町村の人口は「町名の有名さ」を表さない）。B2 の素点（素直 1／変化あり 2／読めない 3）に B4 と **B5 ＝ 同じ表記が全国の町名で 2 通り以上に読まれるか**（本町 ＝ ほんちょう／ほんまち／もとまち）を足す。B5 は **B2 が「素直」のときだけ** +1（連濁の 中島・新橋 まで ★★★ に上げると ★★★ が薄まるため）
  - どちらも ★3 で打ち切る
- **町名の B2 だけ、「変化あり」の認め方を 2 つ広げている**（Issue #54。市区町村名には当てない）:
  - **五段動詞の訓読みの連用形**は「変化あり」。KANJIDIC2 の訓（す.む・ふ.す・な.る）の送り仮名の末尾をウ段からイ段に変えた形（すみ・ふし・なり）で読めれば (b) にする。下一段（あ.ける）は作らない。これで 住吉町・伏見・成田町・有明 が ★★★ から ★★ に落ちる
  - **地名で定着した名乗り読みの表**（[`data/stars_manual.tsv`](data/stars_manual.tsv)）も「変化あり」。1 行 1 読みで字（清＝し・常＝とき）と語（長谷＝はせ）を人が選び、根拠の町名と自治体数を同じ行に残す。これで 清水・春日・常盤町・稲荷町・鍛冶町 などが ★★ に落ちる
  - どちらも **B2 の段階を (b) にするだけ**で、B4（字の難しさ）は効いたまま ＝ 表外・人名用の字を含む町名は ★★★ に残る。表に入れなかった読み（東＝あずま・東雲＝しののめ・河内＝こうち・菅生＝すごう）は難読として ★★★ のまま
- **絞ったら範囲は広げない。** ★ で絞ると 10 問に足りない組み合わせは珍しくない（47 都道府県 × ★ の 141 通りのうち 71 通りが 10 件未満。例 鳥取県 × ★★★ は 5 件）。市区町村名ではそのとき島しょ（9 件）と同じ仕組みで「10 問」を押せなくし、**全市区町村名**（＝その範囲のその ★ を全部）に固定する。町名は逃げ道（全町名）にも下限 10 問があるので固定はせず、**その ★ のボタンを押せなくして理由を出す**（例「東京都・島しょの★★★は 4 問」）。全町名も ★ で絞った結果が 10 問に満たなければ同じく選べない。
- **順位表は難易度で分けない。** 10 問どうしなら ★ を絞っても 1 問の重みは同じで、区分を 3 → 9 に増やすと 1 区分あたりの人数が薄くなるため。代わりに順位表の行に「★★★のみ」と添える。

| 都道府県 | 地域（範囲コード） | 市区町村数 |
|---|---|---|
| 北海道 | 道央 `01c` ／ 道南 `01s` ／ 道北 `01n` ／ 道東 `01e`（道庁の 4 区分。振興局を束ねる） | 70 / 18 / 41 / 50 |
| 東京都 | 23区 `13k` ／ 多摩 `13t` ／ 島しょ `13i` | 23 / 30 / 9 |

- **地域の母集団は広げない。** 都道府県と同じ扱いで、20 件未満でも「範囲が狭いため都道府県に広げました」にしない（道東を選んだのに全道が出るのを避ける）。
- そのため **島しょ × 市区町村名（9 件）は 10 問を組めない**。選択画面では問題数が「全市区町村名（9 問）」に固定される（市区町村名＋町名なら 40 件あるので 10 問を組める）。
- 地図の見出しに出る数は「いまの範囲 × いまの難易度」の **問題数**で、市区町村の数ではない。表記は「67問」「★★★ 26問」で、難易度・科目の切替と一緒に動く（読み上げ名とツールチップは「★★★ の問題数 26 問」）。数の出どころは科目で違い、市区町村名は `easy.json` の件数、町名は `meta.json` の `cities[].townStars` の積み上げ。市区町村の数（`meta.cities`。道央なら 70）を出すのは「10 問を組めない理由」の一文だけ。
- 範囲の表示名は「北海道・道央」「東京都・23区」で統一する（`src/engine/scope.ts` の `scopeLabel` / `rangeLabelOf` が唯一の実装）。
- ランキングは `scope` の**先頭 2 桁**で都道府県にまとめるので、地域のセットも親の都道府県の一覧・件数に入る。

## 画面構成と戻る導線（下タブバー）

全画面の底に **下タブバー 1 本**を置く（`src/components/TabBar.tsx`）。用紙（`.paper`）の外・黒板（`.board`）の中に
`position: fixed` で固定し、タブは 4 枚。

| タブ | 行き先 | 現在地になる経路 |

  `backInPaper` が全画面で 0 であること）。同じ画面の中の移動（地名帳の「← 一覧へ」「前／次」、順位表の
  「都道府県の一覧へ」）は用紙に残す。

  （文面は `src/engine/share.ts` が 1 か所で組む）。

## 時間制限（既定は「なし」）

1 問あたりの制限は端末ごとの設定（localStorage `timeLimitMs`）。**既定は 0 ＝ 制限なし**で、砂時計も残り秒も出さず経過時間だけ測る。20 秒（`20000`）を選ぶと従来どおり 0 で自動パスになる。

- **制限なしと 20 秒は同じ順位表に載る。**並びは得点が主で、所要時間は同点のときのタイブレークにしか効かない。
- 制限ありの行には順位表で「⏳20秒」の印が付く（どちらの条件で解いたかが分かる）。

## 間違えた問題

**ランキングに登録した答案**の誤答（パス・時間切れを含む）だけを端末内（localStorage `wrong:list`・最大 500 件）に残し、`#/review` で新しい順に見られる。解いただけで登録しなかった回は記録しない（10 問でも全市区町村名でも同じ）。同じ問題は最後に間違えたときの入力で上書きする。

## 地名帳（`#/atlas`）

クイズとは別に、**正解（読み）の一覧と位置を眺めるページ**。下タブバーの「地名帳」から入る。`#/atlas` で都道府県を選ぶと「市区町村 ｜ よみ」の表（団体コード順）が出て、行を選ぶと地図でその市区町村が塗られ人口・世帯数・面積・人口密度のカードが出る（`#/atlas/13k/131199` まで URL で指せる）。北海道・東京都は地域で絞れ、**難易度 ★1〜3 でも絞れる**（行の右に ★ が出る。`easy.json` の `stars` を団体コードで引くので、出題から外した 41 件は ★ を持たず ★ を選んでいる間は出ない）。検索は漢字でもかなでも部分一致で、★ と併用できる。載るのは `meta.cities` の 1,741 件すべてで、**出題から外した市区町村（ひらがなの さいたま など）も資料として並ぶ**。900px 以上は出題画面と同じ 2 カラム、899px 以下は一覧と詳細の 2 画面（詳細の「前／次」で隣の行へめくれる）。段階 1 は市区町村名だけで、町名は Issue #35 の段階 2。

## 共有ランキング

同じセットIDで解いた人の順位表。**保存先はビルド時の環境変数 `VITE_RANKING_API` で切り替わる。**

| `VITE_RANKING_API` | ランキングの保存先 | 見える範囲 |
|---|---|---|
| 未設定（既定） | `localStorage`（`LocalRankingStore`） | その端末のその人だけ |
| API のベース URL | AWS の共有ランキング API（`RemoteRankingStore`） | 同じセットIDを解いた全員 |

- 得点は**サーバーが再採点する**。クライアントが送るのは セットID と各問の入力（`input` / `ms` / `passed`）と時間制限（`timeLimitMs`）だけで、点数を申告できない。
- **得点の式**: 10 問のセットは 正答数 × 10。**全市区町村名**（セットID の末尾が `-all`）は問題数が都道府県ごとに違うので、**正答率を 100 点満点に丸めた値**（23 問で 20 問正解なら 87 点）。式は `src/engine/score.ts` の `scoreOf()` 1 か所で、クライアントとサーバーが同じものを使う。
- **全市区町村名・全町名も順位表に登録できる**（以前は練習扱いで登録できなかった）。ただし 1 問の重みが 10 問と違うので、順位表の区分は **3 つ**（市区町村名 / 市区町村名＋町名 / **全問**）に分かれ、同じ一覧には混ざらない。全市区町村名と全町名は「全問」に同居し、行の注記（「全市区町村名（54 問）」「全町名（59 問）」）で見分ける。
- 1 セット 1 登録（セットID × 端末トークン）。登録すると自分の `entryId` を `localStorage['submitted:{setId}']` に残し、順位表の自分の行（`.is-me`）をそれで見分ける。
- 「これまでのランキング」は `#/ranking`（区分＝市区町村名 / 市区町村名＋町名 / 全問 を切り替えて都道府県ごとの回答人数。登録がある県は色が付く）と `#/ranking/{prefCode}`（その区分の上位 30 件。全問の一覧は「正解 20 / 23 問・87 点」のように問題数も見せる）。区分の絞り込みはストア側（Remote なら API の `?mode=`・`mode=all` が全問）で行う。全国（`#/ranking/00`）に全問は無いので選べない。
- API の契約は [`infra/API.md`](infra/API.md)、構成とデプロイ手順は [`infra/README.md`](infra/README.md)。
- GitHub Actions では repository variable `VITE_RANKING_API` を build に渡す（未設定なら空文字 → ローカルランキング）。
- **セットIDの形式を増やしたら、マージ後に `npm run deploy:api` で API を再デプロイする。** Lambda は `src/engine/setId.ts` の `parseSetId` と `bank.ts` をバンドルしているので、再デプロイしないと新しい形式のセットIDが `invalid` で弾かれて登録できない（地域 `01c` 等の 3 文字 scope を足した変更、難易度 `-s{1,2,3}` を足した 2026-10-03 の変更、町名の ★ と全町名を足した 2026-10-05 の変更がこれに当たる）。**順番は Pages → API。** Lambda は問題バンクを `BANK_BASE_URL`（Pages）から読むので、先に API を更新すると `stars` の無い旧 JSON で町名の ★ 絞りが 0 件になる。

## 開発

```bash
npm install
npm run dev        # http://localhost:5173/chimei-kentei/
npm test           # vitest（エンジン・画面・API ハンドラの単体テスト）
npm run build      # dist/ を生成
npm run build:api  # Lambda のバンドル（infra/api/dist/handler.mjs）
npm run deploy:api # 共有ランキング API を AWS へデプロイ（infra/README.md）
npm run build:og   # リンクプレビュー用の public/og.png を og/og.html から撮り直す（Google Chrome が要る）
npm run build:icons # アプリアイコン一式（public/icon-*.png・apple-touch-icon.png）を og/icon.html から撮り直す
npm run build:fonts # 同梱フォント public/fonts/*.woff2 と src/styles/fonts.css を作り直す（uv か fontTools が要る）
npm run measure    # 全画面 × 5 ビューポートの実測（タップ領域・文字・はみ出し・外部ホスト）
npm run build -- --mode capacitor  # ネイティブの殻向けビルド（base を相対にする）
```

- **フォントは同梱**（Google Fonts からは読まない）。5 書体の woff2 はこのアプリに出る字だけのサブセットで、
  字種を増やす変更（UI 文言・問題バンクの版上げ）をしたら `npm run build:fonts` で作り直す。
  ライセンス（SIL OFL 1.1）の全文は `public/fonts/{書体}/OFL.txt` に同梱している。
- **計測**は `npm run build` のあとに `npm run measure`。自分で `vite preview` を立て、ヘッドレス Chrome で
  巡回して `measure.json`・`network.json`・`shots/` を吐く。前後で比べるときは
  `npm run measure -- --json measure-after.json --out shots-after` のように出力先を分ける。
  1 画面に収まっているかは `paper.overY`（0 が正常）で見るが、**用紙ごと縦スクロールする 2 画面**
  （結果・間違えた問題＝`.board--scroll`）だけは `docOverY`・`lastButtonCut`・`reviewVisibleFirstView` で見る。

共有ランキングをつないで手元で試すとき:

```bash
VITE_RANKING_API=https://xxxx.execute-api.ap-northeast-1.amazonaws.com npm run dev
```

`main` への push で GitHub Actions が `dist/` を GitHub Pages に配信する。

### 解答欄（ひらがな専用入力）

- 解答欄に入るのは**ひらがなと長音記号「ー」だけ**。ローマ字で打つと逐次ひらがなになる（`monzen` → 「もんぜん」。打ちかけの子音は `もんぜn` のように画面にだけ残り、Enter / フォーカス外れで確定する）。
- カタカナ・半角カタカナ・全角英数はひらがなへ畳み、漢字・記号・空白は取り除く（`src/components/hiragana.ts`）。
- **IME で漢字に変換されても読みに戻す。** Web から IME は無効化できないので、macOS のライブ変換などで「匝瑳」と確定されても解答は「そうさ」になる。変換中の `keydown` の `code`（物理キー）から打鍵列 `sousa` を組み直すのが主経路で、貼り付けなど打鍵の痕跡が無い場合は `compositionupdate` が最後に「全部かな」だった文字列を使う。かなのまま確定したとき（フリック入力・かな入力）は確定文字列をそのまま使う。変換中の未確定文字列は書き換えない。

```
src/components/TabBar.tsx    下タブバー（戻る導線。枚数と経路の対応は tabs.ts）
src/styles/                  答案用紙テーマ（デザイントークン・部品）
og/                          リンクプレビュー画像（og.html → public/og.png）とアプリアイコン（icon.html → public/icon-*.png）の原稿と撮影スクリプト

```
