# 問題バンク生成（data/build_questions.py）

デジタル庁 アドレス・ベース・レジストリ 全国 町字マスター 2026-09-25 版（CC BY 4.0）を加工して
`public/questions/abr20260925r2/` に問題バンク JSON を書き出す。外部ライブラリ不使用（標準ライブラリのみ）。
出力先の版は `build_questions.py` の `DATA_VERSION`（→ [版の扱い](#版の扱い)）。

```sh
npm run build:questions                      # = python3 data/build_questions.py
python3 data/build_questions.py --abr-dir <dir> --out-dir <dir>   # 入出力を差し替える場合
python3 data/build_questions.py --kanjidic <path> --download      # 難易度に使う KANJIDIC2 の場所／取得
python3 -m unittest discover -s data -p 'test_*.py'               # 前処理ルールの単体テスト
```

**難易度 ★ を付けるため、生成には KANJIDIC2 と人口データが要る**（→ [難易度 stars](#難易度-stars)）。
どちらかが無いと直し方を添えて止まる（黙って `stars` 無しの JSON を書くことはしない）。

## 入力（`~/workspace/abr-data/processed/`）

- `abr_city_reading.csv`（1,892 行）… 市区町村＋政令市の区。`ward` 非空＝政令市の区
- `abr_name_reading.csv`（441,539 行）… `level` = 市区町村 / 大字・町 / 小字
- `public/geo/municipalities.json`（`build_geo.py` の出力）… 難易度 A1 の人口
- KANJIDIC2（既定 `~/workspace/abr-data/raw/kanjidic2/kanjidic2.xml.gz`）… 難易度 B2・B4 の音訓と配当学年。
  **リポジトリには含めない。** 無ければ `--download` か `curl -A 'Mozilla/5.0' -L -o <cache> https://www.edrdg.org/kanjidic/kanjidic2.xml.gz`
- [`data/stars_manual.tsv`](stars_manual.tsv)（リポジトリ内）… 町名の B2 だけに当てる人手の上書き表
  （地名で定着した名乗り読み。→ [上書き表](#上書き表stars_manualtsv)）

## 出力（型は `src/engine/types.ts` の `Question` / `BankMeta`。`ensure_ascii=False`・インデントなし・キー順は宣言順）

- `easy.json` … 市区町村 **1,700 件**（id 昇順）。全 1,741 件から、ルール e で幹に漢字が 1 字も無い 41 件を除いたもの。
  都道府県別の最小は 富山県・福井県・香川県の各 15 件（1 セット 10 問に対して十分）。
  各問の末尾に難易度 `stars`（1〜3）が付く（→ [難易度 stars](#難易度-stars)）
- `difficult/{prefCode}.json` … 大字・町 107,681 件を 47 都道府県に分割（id 昇順。最小 沖縄県 665／最大 愛知県 6,743）。
  各問の末尾に難易度 `stars`（1〜3）が付く（→ [難易度 stars](#難易度-stars)）。
  うち **345 件は `skip: "reading"` が付いて出題されない**（ルール h。`stars` も id も並びもそのまま残る）
- `meta.json` … dataVersion / generatedAt / source / starsNote / skippedReadings / prefectures[47] / cities[1,741]。
  `starsNote` は難易度の軸を 1 文で書いたもの（JSON だけ見ても出自を辿れるようにするための覚え書き）。
  `skippedReadings` は**ルール h で出題から外した件数**（全国 345 件。内訳は町名 345・市区町村名 0）。
  `prefectures[].easyCount` は**除外後**の件数。`cities` は**除外前の全 1,741 件**を残す
  （範囲選択の市区町村検索と difficult の絞り込みに使うため。easy の出題集合とは一致しない）。
  件数の内訳は次の 3 つで、**選択画面はこれだけで全国・都道府県・地域・市区町村の問題数を出せる**
  （17 MB の `difficult/*.json` を読まずに済ませるため。Issue #46）:
  `prefectures[].difficultStars`（その都道府県の町名の `[★1, ★2, ★3]`。合計 = `difficultCount`）／
  `cities[].towns`（その市区町村の町名の件数。0 の市区町村が 33 件）／
  `cities[].townStars`（その `[★1, ★2, ★3]`。合計 = `towns`）

  **この 4 つの件数（`easyCount` / `difficultCount` / `difficultStars` / `towns` / `townStars`）は
  「出題できる件数」＝ `skip` を除いた数**で、JSON の配列の長さとは一致しない
  （町名は配列 107,681 件に対して出題できるのは 107,336 件。Issue #50）。

## 前処理ルール（設計 §4）

- **a** `(pref, city)` で一意化。政令市は区の行をまとめて 1 市、郡名は使わない。政令市の `lgCode` は区コードの
  先頭 4 桁＋`'0'`＋全国地方公共団体コードの検査数字（6,5,4,3,2 加重和 → 11−余り、10 以上は 1 の位）。例 札幌 `011002`／川崎 `141305`。
- **b** 末尾 1 文字（市区町村）を `suffix` に分離し、読みからも シ/ク/チョウ|マチ/ソン|ムラ を外す。剥がせなければ例外で停止。
- **c** difficult は `level=='大字・町'` かつ `n_readings=='1'` かつ `kana_small_suspect=='False'` の行のみ。
- **d** 先頭の冠「大字」「字」を外す。読みが オオアザ/アザ のどちらで始まっても外す（どちらでもない 368 件は漢字のみ）。
- **e** 「漢字」は `々`・`〆` を含む（`KANJI_CLASS`）。difficult と easy で要求が違う。
  - difficult … 幹が**漢字のみ**で構成される行だけ残す（数字・カナ・記号を含む 11,987 件を除外）。
    ほか複数読み 596 件・`kana_small_suspect` 5,672 件・空 1 件を除外（`level=='大字・町'` 127,894 → ルール c 通過 121,626）。
  - easy … 幹に**漢字が 1 字以上**あるものだけ残す（`has_kanji()`）。「せたな」「ニセコ」「つくばみらい」のように
    かなだけで書かれた 41 件は、読む問題にならず見ただけで得点できてしまうので除外する（Issue #14）。
    「鎌ケ谷」「ふじみ野」「南アルプス」のように漢字とかなが混ざるものは読みとして成立するので残す。
- **f** 丁目は対応表で分離済みのため何もしない。**g** `status_flg` は対応表に無いため何もしない。
- **h** 読みが `^[ぁ-ゖー]+$` に合わない問は **`skip: "reading"` を付けて出題から外す**（Issue #50）。
  該当は町名 **345 件**（市区町村名は 0 件だが同じ判定を通す）で、混ざる文字はすべて**全角数字**
  — デジタル庁のカナが漢数字を数字で書いているもの（西十一条北 ＝ にし１１じょうきた／
  端野町一区 ＝ たんのちょう１く）。解答欄（`src/components/HiraganaInput.tsx`）はひらがなと「ー」しか
  受け付けないので、このままでは**正解できない問題**になる。
  - **数字を読みに直さない。** 一線 ＝ いっせん／一区 ＝ いっく／四条 ＝ よじょう・しじょう と、
    数の読みは後ろの字と土地で変わる。機械で付けた読みを「正解」にすると誤りが増える
  - **JSON からは消さない。** 抽出（`src/engine/sampler.ts`）は id 順の母集団を setId の乱数で
    部分シャッフルして選ぶので、母集団から 1 件消すとその範囲のセットがすべて別の 10 問になる。
    印を付けて残し、抽出側が飛ばすことで、**skip を引いていなかった既存セットは同じ 10 問のまま**になる
  - **`stars` は付けたまま**にする。★ の B5（同表記異読み）は母集団全体で数えるので、
    `skip` は ★ を付けた**あと**に通す（先に外すと残る町名の ★ が動く）。
    なお 345 件はすべて ★★★（読みを音訓で分解できない ＝ B2 (c)）なので、
    `difficultStars` の減りは ★★★ だけに出る
  - 都道府県別の件数: 北海道 109／宮城 80／静岡 49／青森 31／徳島 18／兵庫 15／香川 9／大阪 7／
    愛媛 5／山形・長野・岐阜 各 4／高知 3／秋田・三重 各 2／岩手・愛知・奈良 各 1（18 都道府県）

## 難易度 stars

`easy.json`（市区町村名）と `difficult/*.json`（町名）の各問に付く ★1〜3。
**判定の正本は [`build_stars.py`](build_stars.py)**（Issue #33 / PR #38・Issue #46・Issue #54）で、
`build_questions.py` は `judge_all()` / `judge_towns_with_rules()` を呼んで結果を書き込むだけ。
**軸・表・閾値はここにも写さない**（写すと必ず食い違う）。要点だけ:

- 市区町村名（`judge_all`）… A1 人口 × B2 漢字の音訓で公式の読みを分解できるか × B4 幹の中で最も難しい漢字、
  の 3 軸。B2×A1 の素点に B4 を足して ★3 で打ち切る
- 町名（`judge_towns`）… **A1 は使わない**。B2 の素点（a 素直 1／b 変化あり 2／c 読めない 3）に B4 と
  B5（同じ表記が全国の町名で 2 通り以上に読まれる。**B2 が a のときだけ** +1）を足して ★3 で打ち切る
- **町名の B2 だけ (b) 変化あり の認め方が 2 つ広い**（Issue #54。市区町村名には当てない ＝
  `judge_all` は従来どおり名乗りを (c) に置く）:
  **五段動詞の訓読みの連用形**（`renyokei_forms`。す.む → すみ・ふ.す → ふし・な.る → なり。
  下一段の あ.ける → あけり は作らない）と、**地名で定着した名乗り読みの表**
  （[`stars_manual.tsv`](stars_manual.tsv) → [上書き表](#上書き表stars_manualtsv)）。
  どちらも B2 の段階を (b) にするだけで B4 は効いたまま（表外・人名用の字を含む町名は ★★★ に残る）
- **A1 の分位点は渡した問題全体から取る**ので、`judge_all()` には **easy 全件をまとめて渡す**こと。
  都道府県ごとに呼ぶと帯の境界がずれる。**B5 も同じ理由で `judge_towns()` には difficult 全件をまとめて渡す**
  （都道府県ごとに呼ぶと「本町 ＝ 3 通り」が県内の通り数に縮む）
- 既定（`--major-exempt` なし）での分布は、市区町村名が ★ 566 / ★★ 601 / ★★★ 533 件、
  町名が ★ 38,863 / ★★ 46,754 / ★★★ 22,064 件（JSON の配列 107,681 件。ルール h の
  `skip` 345 件を除いた「出題できる」分布は ★ 38,863 / ★★ 46,754 / ★★★ 21,719 件）
- `build_stars.py` を単体で動かすと JSON は書き換えず、分布・クロス集計・アンカーの検算だけを出す。
  **軸を変えたら `npm run build:questions` で問題バンクを作り直す**
- 同一 `lgCode`・同一 `display` の重複は、`answer` が一致すれば 1 件に集約（1,715 件を除外）。
  `answer` が割れて正解を一意にできない 115 display（242 行）はキーごと全件落とす。

## 版の扱い

`DATA_VERSION`（= 出力ディレクトリ名 = `setId` の先頭）は、**出題内容が変わったら必ず上げる**。
`setId` は `{dataVersion}-{mode}-{scope}-{seed}` で、クライアントと API はこの seed から
問題バンクの並びに依存して 10 問を抽出する。版を据え置いたまま母集団を変えると、
既存の共有リンク・順位表が「同じ setId なのに違う 10 問」を指すことになる。

| 版 | 出力先 | 中身 |
|---|---|---|
| `abr20260925` | （削除済み） | 初版。easy 1,741 件。2026-10-04 に削除（Issue #42） |
| `abr20260925r2` | `public/questions/abr20260925r2/`（現行） | easy 1,700 件（ルール e を easy にも適用し 41 件を除外）。difficult と `meta.cities` は初版と同一。2026-10-05 にルール h（`skip: "reading"` 345 件）を足したが**版は据え置き**（下記） |

**ルール h（Issue #50）は版を上げずに入れた。** 原則は「出題内容が変わったら必ず上げる」だが、
`skip` を**配列から消さずに印として足す**ことで、母集団の並びと件数が変わらず、
**`skip` を引いていなかったセットは前と同じ 10 問を再現できる**（抽出側が飛ばすだけ）。
変わるのは `skip` を引いていたセット ＝ もともと正解できない問題を含んでいたセットだけなので、
全国の市区町村名を含むすべての既存セット ID を「古い版」にして開けなくするより釣り合いがよい
（0.3% の町名のために 100% を無効にしない）。**ただしマージ後の `npm run deploy:api` は必要**
（Lambda がエンジンを同梱しており、抽出が変わるため。再デプロイ前は `skip` を引いていたセットの
登録だけ `invalid` になる）。

**同梱するのは現行版 1 つだけにする。** スマホアプリ（Capacitor の殻）に `public/` をまるごと
入れる都合で、使っていない版を 17MB ぶん抱えると配信サイズが倍になるため（設計ノート §13.6 決定 6）。
旧版の setId を `#/q/` や `#/result/` で開いたときは、黙って現行版で組み直さず
「この問題セットは古い版のため開けません」と出して止める（`src/engine/bank.ts` の
`OUTDATED_SET_MESSAGE`）。順位表に残っている旧版の行は触らない（Issue #11 の範囲）。

### 版を上げたときの手順（順序が大事）

`DATA_VERSION` は 2 か所にあり、**必ず同じ値**にする。

1. `data/build_questions.py` の `DATA_VERSION`
2. `src/engine/bank.ts` の `DATA_VERSION`（クライアントと Lambda が共有する）

そのうえで:

1. `npm run build:questions` で新しい版のディレクトリを生成し、**旧版のディレクトリを消す**
2. マージ → GitHub Pages のデプロイ（新しい版の JSON が公開される）
3. **`npm run deploy:api` で Lambda を更新する**（`infra/README.md` の「デプロイ」）

3 を忘れると、Lambda は旧版の `DATA_VERSION` を同梱したままなので、新しい版の setId で登録しようとすると
「この版では再現できない setId です」で 400 になる。**2 と 3 のあいだは共有ランキングへの登録ができない。**
なお、クライアントの `buildQuestionSet` は setId に書かれた版を見ず常に現行の `DATA_VERSION` で再導出するので、
旧 setId の共有リンクを開くと新しい版で 10 問が引き直され、結果画面と登録は新しい setId で行われる。

cd data && uv sync                  # 初回のみ（geopandas / shapely / pyogrio / pandas）

## 水面調査区（HCODE=8154）は除外する

全国 232,019 小地域の `HCODE` は `8101`（通常の調査区）231,668 件と `8154`（水面調査区）351 件の 2 値のみ。
**8154 は面積・人口・世帯の集計からもポリゴンからも除く。**公称面積との比較で明らかに近いため。

| 市 | 公称 | 8154 を含む | 8154 を除く（採用） |
|---|---|---|---|
| 千葉県匝瑳市 | 101.52 km² | 101.61 (+0.09) | 101.61 (+0.09) ※水面調査区なし |
| 大阪市 | 225.33 km² | 251.98 (**+26.65**) | 220.28 (−5.05) |
| 札幌市 | 1,121.26 km² | 1,121.19 (−0.07) | 1,121.19 (−0.07) ※水面調査区なし |

水面調査区を持たない匝瑳市・札幌市は `AREA` の合計がそのまま公称面積と ±0.1 km² で一致する。
大阪市のように港湾を抱える市だけが分かれ、含めると +26.65 km²、除くと −5.05 km²。名古屋市も同様（−3.27 km²）で、
**除いたほうが一桁近い**。残る過小は、埋立地の一部が水面調査区に含まれているため（`--keep-water` で再現できる）。
人口への影響は全国で 23 人（水面調査区に住む船上生活者等）。

## ジオメトリの処理

1. **`make_valid`** で無効ポリゴンを直す（全国 130 件）。`buffer(0)` は面を削るので使わない
2. **`set_precision(1e-4)` で格子にスナップしてから dissolve する。** e-Stat の小地域は隣接ポリゴンの境界座標が
   完全一致しないため、そのまま溶かすと市区町村ポリゴンの内部に幅 cm 級のスリーバー穴が大量に残る。
   北海道では穴 19,916 個で、1 穴＝最低 4 頂点が削れないので `coverage_simplify` が効かなくなる
   （tolerance をいくら上げても 161,579 頂点で飽和）。スナップ後は同じ tolerance で 20,625 頂点まで落ちる
3. 残った **0.01 km² 未満の穴を埋める**（全国 16,843 個）。実在の飛び地（例 和歌山県北山村 48 km²）は閾値よりはるかに大きいので消えない
4. 簡略化は **`shapely.coverage_simplify`**（面の被覆の共有境界を保つ）。座標は小数 4 桁（≒11 m）に丸め、
   丸めで重なった連続点をつぶす。統計の代表点だけ 5 桁

### tolerance は県ごとに自動調整する

下限 **0.002 度（≒220 m）**から、1 ファイル 300 KB に収まるまで 1.5 倍ずつ上げる。
引き上げが要るのは **北海道だけ（0.00675）**で、残る 46 県は下限のまま。
ポリゴン面積の誤差は中央値 0.25%・最大 2.9%（小値賀町などの離島の町）。

### japan.json は「簡略化済みの市区町村」から作る

生の市区町村ポリゴンを溶かして全国の被覆にすると、**県境の座標が県ファイル間で一致しない**（`coverage_is_valid` が False）。
GEOS は潰せない辺を残すので、関東 10 県だけでも 26,000 頂点で飽和し、全国では 150,000 頂点＝2.9 MB になった。
県内で先に簡略化してから溶かすと、不一致の元になる細かい頂点が先に消え、全国 47 県が 12,000 頂点まで落ちる。

- 15 km² 未満の島を落とす（全国 17,373 個）。沖縄本島・宮古島・石垣島・佐渡・隠岐島後・五島福江島・奄美大島・小笠原父島は残る
- 20 km² 未満の穴を埋める（境界未定地など 2,590 個）
- tolerance は 0.006 度から 1.5 倍ずつ上げるが、**上限 0.03 度（≒3.3 km）で打ち切る**。
  上の理由で coverage_simplify は 9,000 頂点付近で飽和しており、それ以上上げてもサイズは減らず形だけ崩れる
  （0.0683 度では沖縄県の面積が −21% になるのに 173 KB までしか縮まない）
- 結果は **188 KB**で、目標の 150 KB には届かない。県境は隣り合う 2 県が別々に持つため頂点が二重に乗るのが主因。
  面積誤差は中央値 0.41%、最大は沖縄県 11.8%・香川県 7.5%（どちらも落とした小島のぶん）

# 難易度 ★ の試作（data/build_stars.py・Issue #33・#46・#54）

地名の各問に ★1〜★3 を機械的に付ける。`build_questions.py` から呼ばれて
`easy.json` / `difficult/*.json` の `stars` を書くのがこのスクリプトで、単体で動かすと
JSON は書き換えず分布・クロス集計・アンカーの検算だけを出す（軸を試すための道具を兼ねる）。

- 市区町村名（mode `e`・`judge_all`）… Issue #33 の軸のうち **A1（人口による知名度）**・
  **B2（漢字の音訓辞書で公式読みを分解できるか）**・**B4（漢字の難しさ）** の 3 軸。
  B2×A1 の表で素点を出して B4 で加算する
- 町名（mode `d`・`judge_towns`）… Issue #46 の案 C。**A1 は使わない**。B2 の素点に B4 と
  **B5（同表記異読み・B2 が (a) のときだけ +1）** を加算する（→ [町名の ★](#町名の-judge_towns)）。
  さらに町名だけ、(b) に **五段動詞の連用形** と **人手の上書き表** を入れる（Issue #54。
  → [上書き表](#上書き表stars_manualtsv)）

```sh
python3 data/build_stars.py                                   # 帯の境界・★ の分布・アンカーの検算
python3 data/build_stars.py --sample 100 --seed 20261003 \
    --markdown /tmp/sample100.md                              # サンプルの Markdown 表
python3 data/build_stars.py --json /tmp/stars.jsonl            # 全 1,700 件の判定（検算用）
python3 data/build_stars.py --nanori b                        # 名乗り読みを (b) 扱いにした場合
python3 data/build_stars.py --major-exempt                    # 政令市・県庁所在地は B4 加算を免除
python3 data/build_stars.py --towns                           # 町名（B2×B4×B5）の分布と既知例の検算
python3 data/build_stars.py --towns --sample 100 --seed 20261005 \
    --markdown /tmp/towns100.md                               # Issue #46 のサンプル表を再現する
python3 data/build_stars.py --towns --manual /dev/null        # 上書き表を外したときの町名の分布
python3 -m unittest data/test_build_stars.py                  # 分解判定の単体テスト
```

`--towns` は **before（町名だけの軸なし）→ after（連用形 ＋ 上書き表）** の分布、
(c) から (b) へ動いた件数（規則だけ／上書き表だけ／両方）、**上書き表の行ごとに効いた件数**
（0 件の行は ⚠ で目立たせる）、既知例の検算を毎回出す。

## 入力と判定

- **A1** … `public/geo/municipalities.json` の `population`（国勢調査 2020）を全国一律の分位点で 3 帯に切る。
  有名 ≥ p80（79,306 人・341 件）／無名 < p40（14,959 人・680 件）／間はふつう。
  政令指定都市 20 市と都道府県庁所在地が全件「有名」帯に入ることを実行時に検算する（外れたら警告）
- **B2** … KANJIDIC2 の音読み・訓読みで `display` を 1 字ずつ区切り、`answer` を左から消費できるかを DP で判定。
  (a) 素直（音訓そのまま。訓は送り仮名をどこまで読むかのゆれを許す）1,012 件／(b) 連濁・半濁音化・促音化・
  長音のゆれ・末尾の母音の脱落が要る 279 件／(c) それでも無理（熟字訓・当て字・助詞「の」の挿入）409 件。
  「々」は直前の字の読みを引き継ぐ。「ケ」「ヶ」は助詞「が」として読める
- **B4** … KANJIDIC2 の `<grade>` で漢字 1 字の難しさを 4 段階にし、**幹の中で最も難しい 1 字**で決める。
  漢字以外（かな・ケ・ノ・々）は 0 扱い

  | ランク | `<grade>` | 件数 | 素点への加算 |
  |---|---|---:|---|
  | 0 教育 | 1〜6（教育漢字） | 1,006 | +0 |
  | 1 常用 | 8（中学で習う常用漢字） | 428 | +0 |
  | 2 人名用 | 9・10（人名用漢字） | 230 | +1 |
  | 3 表外 | 無し（常用漢字表外） | 36 | +2 |

- **総合** … `STAR_TABLE`（(a)/(b)/(c) × 有名/ふつう/無名）の素点に `B4_BONUS` を足し、★3 で打ち切る。
  判定の根拠は `--json` の `b2detail`・`b4detail`・`baseStars`・`b4Bonus` で 1 問ずつ追える。
  ★ の分布は **★ 566（33%）／★★ 601（35%）／★★★ 533（31%）**（B4 で 194 件が 1 段上がった）

### B4 の加算値を選んだ理由

- **常用（8）は +0。** +1 にすると「横浜」（浜 は grade 8）が ★2 に上がってアンカーを外す
- **表外は +2。** +1 だとアンカーの「匝瑳＝★3」に届かない（素点が ★1 なので ★2 で止まる）。
  表外は全 1,700 件中 36 件しかないので、+2 でも ★3 が膨らみ過ぎない
- **JIS 水準は使わなかった。** 難読の代表である「匝」（匝瑳市）が JIS X 0208 **第 1 水準**に入っており
  （区点 1-33-57）、水準では拾えない。`<grade>` が無いこと（＝常用漢字表外）のほうが「読めなさ」をよく表す

**名乗り読み（KANJIDIC2 の `<nanori>`）は (b) に入れず (c) に残している。** `<nanori>` には
「その地名があるからこそ辞書に載っている読み」が含まれるため（宿=すく ← 宿毛／南=は・風=え・原=ばる ← 南風原）、
(b) に昇格させると当て字が ★2 に落ちる。`--nanori b` で Issue のたたき台どおりの挙動に戻せる。

## 町名の ★（`judge_towns`）

Issue #46 の案 C。**A1（人口）は使わない** — 町名に人口は無く、所属市区町村の人口は
「町名の有名さ」を表さないため。代わりに手元の対応表から取れる **B5（同表記異読み）** を使う。

| 軸 | 値 | 加算 |
|---|---|---|
| B2 | (a) 素直 61,670（57%）／(b) 変化あり 30,320（28%）／(c) 読めない 15,691（15%） | 素点 1 / 2 / 3 |
| B4 | 教育 61,833 ／ 常用 29,807 ／ 人名用 13,310 ／ 表外 2,731 | +0 / +0 / +1 / +2（`B4_BONUS`。市区町村名と同じ） |
| B5 | 同じ表記が全国の町名で 2 通り以上に読まれる 25,233 件（本町 ＝ ほんちょう／ほんまち／もとまち） | **B2 が (a) のときだけ** +1（効いたのは 15,771 件） |

- ★3 で打ち切る。全 107,681 件の分布は **★ 38,863（36%）／★★ 46,754（43%）／★★★ 22,064（20%）**
- **B5 を (b)・(c) にも足さない。** 足すと 中島（なかじま・連濁）や 新橋（しんばし・連濁）が ★★★ に上がり、
  ★★★ が 31% まで膨らんで薄まる。本町（ほんちょう ＝ 素直 ＋ 異読み）が ★★ に上がるのが狙い
- **B5 は渡した町名全体で数える。** `judge_towns()` には **全国 107,681 件をまとめて渡す**こと
  （都道府県ごとに呼ぶと「本町 ＝ 3 通り」が県内の通り数に縮む）
- 判定の根拠は `--json` の `b2detail`・`b4detail`・`readings`・`b5`・`verbStem`・`manual`・`baseStars`
  で 1 件ずつ追える
- どの都道府県でも ★ 別に 150 件以上あるので、**都道府県単位なら ★ で絞っても 10 問は必ず組める**
  （足りなくなるのは東京都・島しょ 19 件のような地域だけ）
- 既知例の検算（`TOWN_ANCHORS`）は `--towns` で毎回出る。放出東・舎人・御器所・東雲町・雑餉隈町・
  立売堀・太秦・等々力・馬喰町 = ★★★ ／ 中島・新橋・本町・栄町・山田・大平・白金・伏見・成田町・
  住吉町・有明・清水・春日・常盤町・長谷 = ★★ ／ 中央・十三 = ★

## 上書き表（`stars_manual.tsv`）

**名乗りでしか分解できない町名が 14,560 件（13.5%）あり、素のままでは (c) ＝ ★★★ に入る**
（伏見・常盤・有明・住吉町・成田町 のような誰でも読める町名まで ★★★ になる）。
名乗りを一律 (b) にすると 11,947 件が ★★ に落ちて分布が 36 / 49 / 15 になり ★★★ が当て字で
なくなるので（Issue #33 で却下）、**規則で導ける形と人が選んだ読みだけ**を (b) にする（Issue #54）。

- **規則**（`renyokei_forms`）… 五段動詞の訓読みの連用形。送り仮名の末尾がウ段ならイ段に変えた形を
  (b) の候補に足す（す.む → すみ・ふ.す → ふし・な.る → なり・と.まる → とまり）。
  末尾が「る」で直前がエ段なら下一段なので作らない（あ.ける → あけり は作らない。
  接頭辞 あけ は `kun_forms` が既に出す）。音便のゆれ（住＝ずみ・泊＝どまり）も通る
- **上書き表**（`stars_manual.tsv`）… 1 行 1 読みのタブ区切り。`kind`（`kanji` か `word`）／
  `key`（字または語）／`reading`／`note`（根拠の町名と自治体数）。`#` 始まりはコメント。
  `kanji` 行は 1 字に読みを足し（清＝し・常＝とき・盤＝わ）、`word` 行は語をまとめて
  1 セグメントとして読む（長谷＝はせ）

```
kanji	清	し	清水 62・清水町 47+10・大清水 9
word	長谷	はせ	長谷 10
```

- **行を足したら `npm run build:questions`**（問題バンクの `stars` を作り直す）。効いた件数は
  `python3 data/build_stars.py --towns` が行ごとに出すので、**0 件の行＝消してよい行**が分かる
- **市区町村名（`easy.json`）には当てない。** 規則を当てると登別・盛岡・成田・会津若松 など 30 市の
  ★ が動き、★★★ から外れる市が出ると「今日の10問」（全国 × 市区町村名 × ★★★）の過去の日付の
  セットが全部別の 10 問になる。市区町村名への適用は次の版上げと一緒に行う（Issue #11）
- 採らなかった読み（東＝あずま・東雲＝しののめ・河内＝こうち・菅生＝すごう）は難読として ★★★ に残す
- この 2 つで **5,823 件が ★★★ → ★★** に落ちた（(c) から (b) へ動いたのは 6,909 件で、残りは
  B4 ＝ 人名用・表外の加算で ★★★ のまま）

## 既知の限界

アンカー 11 件のうち **9 件が一致**する（B4 を入れる前は 7 件。小樽・高槻・匝瑳 が直った）。残る 2 件:

- **札幌市**（期待 ★1 / 判定 ★2）… 「幌」が人名用漢字なので +1 される。小樽（★2 が期待値）と
  A1 の帯も B4 のランクも同じで、違うのは人口の桁（197 万 vs 11 万）だけ。A1 の帯を増やさずに
  分けることはできない。`--major-exempt`（政令市・県庁所在地は B4 加算を免除＝Issue #33 の軸 A2）を
  付けると ★1 に戻り、アンカーは 10/11 になる。既定では付けていない
- **八重瀬町**（期待 ★3 / 判定 ★1）… 八・重・瀬 はすべて常用漢字以内で、読み「やえせ」も
  辞書にある訓（重＝え）だけで割れてしまう。難しさの出どころは「その訓がこの地名以外で使われない」
  という**読みの珍しさ**で、Issue #33 の軸 B3（多読み漢字・読み候補の数）か B5（同表記異読み）の領分
